# SilentSense CSI-ID Web Demo

Self-contained, browser-based demo that lets you

- inspect a random CSI amplitude sample from NTU-Fi HumanID (14 subjects) or NTU-Fi HAR (6 activities),
- see what every trained model predicts for that sample (top-5 softmax, correct/wrong verdict),
- compare all models at a glance (per-sample + across the demo pool),
- browse the 10-seed aggregated performance leaderboard (accuracy / F1 / params / latency / peak GPU memory / train time).

## Files

| Path | What it is |
| --- | --- |
| `index.html` | The UI. Single file, vanilla JS + CSS. |
| `data.json` | Predictions, class labels, and the aggregated performance table. Regenerated by `scripts/build_demo_assets.py`. |
| `heatmaps/*.png` | CSI amplitude heatmaps for each demo sample (viridis, antenna-averaged). |
| `ckpt/<dataset>/<model>.pt` | Freshly retrained weights used by the builder. Not needed at serve time. |

## Run it

```bash
python3 -m http.server 8000 --directory demo
# open http://localhost:8000/
```

Any static file host works (GitHub Pages, S3, Netlify …). Just copy `index.html`, `data.json`, and `heatmaps/` together.

## Regenerate the bundle

```bash
# 1. (re)train demo models (CPU, ~45 min for 7 models × 2 datasets)
python3 scripts/retrain_demo_models.py

# 2. build data.json + heatmaps from the fresh checkpoints + summary.csv
python3 scripts/build_demo_assets.py --samples-per-class 2
```

`build_demo_assets.py` uses only `demo/ckpt/<dataset>/<model>.pt` (legacy weights under `model_pt*/` were stale and are ignored).

## Notes

- Class ordering matches `wisense.dataset.CSI_Dataset` (filesystem order from `glob.glob`, not alphabetical).
- Mamba is excluded on CPU builds (requires `mamba-ssm`, which in turn needs CUDA).
- The per-model accuracy bars in the UI are computed by the builder via actual CPU inference on the demo samples, so they reflect the specific held-out samples shown — not the 10-seed aggregate.
